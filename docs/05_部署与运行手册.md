# PaperAgent V1 Windows 部署与运行手册

需要 Windows、Python 3.13、Node.js/npm、Git 和 MySQL；本机验证版本与依赖锁定文件见 `后端/requirements.txt`、`前端/package-lock.json`。确保 `.env` 不被提交。MySQL 应使用隔离的 `paper_agent` 数据库和专用账号，不要使用其他项目数据库。

1. 在 `后端` 目录创建虚拟环境并执行 `.venv\Scripts\python.exe -m pip install -r requirements.txt`；在 `前端` 执行 `npm ci`。在受信任环境审查依赖及版本。
2. 复制 `后端/.env.example` 为 `.env`，填写 MySQL 专用账号和密码、GLM 的 `LLM_API_KEY`、`LLM_MODEL` 和供应商 `LLM_BASE_URL`。不把秘密写入仓库或前端；同名进程环境变量优先于 `.env`。缺少密钥时项目页面可启动，真实模型调用不可用。Crossref 使用现有公开接口，受网络和供应商可用性约束。
3. 数据库升级前确认目标、账号、备份和迁移链；在后端运行 `.venv\Scripts\python.exe -m alembic current` / `heads`，审查后由有权限的维护者运行 `alembic upgrade head`。MySQL DDL 可能隐式提交，不提供破坏性自动回滚；不要对有价值的数据直接实验。
4. 启动现有 MySQL 后双击 `启动 PaperAgent.bat`。启动器只监听 127.0.0.1、检查 8000/5173、数据库专用账号、健康及代理，成功后打开浏览器。停止用 `停止 PaperAgent.bat`，仅对记录且验证身份的进程树操作。日志与状态在 `logs/`；端口占用需人工确认，不按端口杀进程。工具不安装依赖、运行迁移或启停 MySQL。
5. 也可在后端执行 `.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`，前端执行 `npm run dev -- --host 127.0.0.1`。`/health` 只表明 HTTP 服务存活，项目 GET 才涉及数据库。生产部署需自行配置 HTTPS、认证及 API/History 路由，当前未作为 V1 交付。

模型及搜索服务可能收费或限流；结果不确定的请求应先核对账本，禁止盲目重试。备份数据库与 SQLite 文件需一致性规划及访问控制；两者不具有事务一致性，不能保证恢复后自动对齐。
