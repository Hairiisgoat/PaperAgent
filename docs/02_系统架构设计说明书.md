# PaperAgent V1 系统架构设计说明书

## 总体链路

Vue 3 / Pinia / Router → Axios / fetch SSE → FastAPI Router → Service → Repository / SQLAlchemy → MySQL。GLM 通过 LLMService / GLMClient；Research 访问 Crossref；LangGraph SQLite Checkpointer 保存流程快照。前端不直连数据库。接口与项目范围校验不等于用户身份鉴权。

项目后端 `app/api`、`schemas` 负责 HTTP 和契约；`services` 协调业务、事务和任务；`repositories` 提供数据访问；`models` 是 ORM；`graph` 构造不同版本流程；`agents` 保留 Mock；`infrastructure` 封装数据库、GLM、检索和 Checkpointer 等适配。前端 `views`、`components`、`stores`、`services` 和 `types` 分别承担页面、组件、状态、接口与类型职责。当前 services 内容较多，未来可按业务域拆分；不建议为目录整洁而大规模重构。

## Agent 与运行

Planner 产出任务并持久化，人工审核后 Research 检索和去重，资料再次审核后 Writing 分段生成，Review 在写作完成后独立启动并绑定章节版本。真实 Review 有自己的报告、单元和模型调用记录，并非现有 graph factory 中串联的 Review 节点。用户可对指定章修改或恢复历史版本，审查随版本变化成为历史快照。

`graph_version` 固定既有运行的图语义；`mock_v1`、`planner_real_v1`、`planner_research_v2`、`planner_research_writing_v3`、`planner_research_writing_v4` 由工厂显式选择。`thread_id` 在暂停/恢复中稳定；`run_id` 是单次尝试，恢复创建新 run；审核决定幂等持久化。`PaperAgentState` 主要保存项目、任务/来源/生成记录 ID 和用量摘要；MySQL 为正文、版本和业务记录权威源，SQLite 保存状态及中断。两库与外部供应商无原子事务。

队列启动恢复仅适合本机单进程；已发送但结果未知的调用保留 `needs_review`，不能盲目自动重试。Checkpoint、账本、事件可能不一致，需人工对账；用量缺失不是零。SSE 的持久化事件按每 run 顺序重放，临时文本和心跳不保证重放，内存广播不支持多进程。日志与客户端应避免秘密及异常原文。
