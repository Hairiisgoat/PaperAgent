# M2-08-01 GLM 调用基础设施

本阶段不改变 Mock Agent 或工作流。按需使用 `LLMService.from_settings()` 创建服务；使用已安装的 `langchain_core.messages` 构造文本消息并调用 `invoke`。适配器通过现有 httpx 发起一次非流式 Chat Completion；不自动重试、不跟随重定向，也不使用环境代理。结果只包含文本、可空的使用量与未知成本，不包含供应商完整响应。

在后端 `.env` 本机配置（禁止提交真实值）：

```dotenv
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-5.3-flash
LLM_API_KEY=在本机填写新密钥
LLM_TIMEOUT_SECONDS=30
```

环境变量优先，加载发生在创建 LLMService 时；没有模型配置或密钥不影响 FastAPI 启动。必须使用 HTTPS；如改变地址，务必确保是可信供应商地址，因为请求会携带密钥。模型代码依据智谱官方文档，具体账号权限和可用性需实测确认。请勿将 `.env`、密钥、完整 Prompt 或响应写入 State、Checkpoint、数据库或日志。

```python
from langchain_core.messages import HumanMessage
from app.services.llm import LLMService
from app.infrastructure.glm_client import UsageAccumulator

service = LLMService.from_settings()
totals = UsageAccumulator()
result = service.invoke([HumanMessage(content="Hello")], max_tokens=64)
totals.add_result(result)
# 将 totals.snapshot() 写入 PaperAgentState 的 budget_accounting。
# result.text 是供调用方即时处理的文本，不应放入长期 State。
# totals.budget_usage 为完整计量时的轻量两字段；用量缺失时为 None。
```

`UsageAccumulator` 按每次请求生成的 UUID 去重。`snapshot()` 返回 known_usage、complete、call_ids，可写入 PaperAgentState 的 budget_accounting 并经 Checkpointer 保存；从状态恢复调用 `UsageAccumulator.from_state(state)`。旧 Checkpoint 缺少完整性或调用 ID 时默认为不完整，不能虚构已统计的调用身份；缺失或非法 usage 会永久保持不完整，`known_usage` 只是已知部分。该实例仅限单线程使用，不能跨并发节点共享；并发合并需要另行设计。当前没有真实 Agent 把快照写入工作流，也不计算价格，成本未知。Checkpoint 不保证与 MySQL 或供应商 API 的 exactly-once 计费。

LLMError 的 code 是安全分类，异常消息不含供应商原文、Prompt 或密钥；不承诺供应商错误码与 HTTP 状态完全一一对应。默认离线测试使用 httpx MockTransport。仅由用户明确设置 `PAPERAGENT_LLM_LIVE_TEST=1` 才可运行 `python -m pytest -s tests/unit/test_llm.py -k live`；该测试发送一次受限请求，可能产生费用。模型会消耗思考 token，过小的 max_tokens 可能导致无法获得文本响应。

## 安全诊断（M2-08-01-DEBUG）

调用失败时，`LLMError` 保留 `code`、`error_category`、`http_status`、`request_stage`、`retryable` 和 `provider_request_id`。异常文本仍仅包含固定分类；不保存供应商正文或原始异常。404 只表示资源未找到，不推断地址或模型哪个有误；非 JSON 与 JSON 内容结构不合法分别归类。仅接受响应头中规范 UUID 格式的 request ID；其余格式丢弃。连接失败通过底层 `socket.gaierror` 识别 DNS，否则分类为 connection，不输出异常详情。`retryable` 统一保守为 false；`outcome` 区分 not_sent（本地校验或连接未建立）、rejected（供应商明确返回 4xx）、unknown（超时、网络、5xx 等结果不确定）和 received（HTTP 200 已返回但解析或内容失败）。不允许 Agent 仅凭 `retryable` 自动重试，不确定结果需人工或专门的幂等和计费对账方案。

`LLM_BASE_URL` 需填写包含服务路径的完整 base URL。实现去除末尾斜杠并追加 `/chat/completions`，不会自动转换普通 API 与 Coding Plan 路径，也不会调整模型名大小写。发往 Z.AI 的请求需要用户自行确认订阅、密钥权限、模型代码及相应地址。真实测试失败时使用 `-s` 可看到安全分类，即使 pytest 使用 `--tb=no` 也不会丢失；不要打印完整异常、请求或响应。

## 响应结束原因（M2-08-01-RESP-FIX-01）

该客户端仅支持非流式最终文本：需要 `choices[0].finish_reason == "stop"`、非空白字符串 `message.content`，且不能携带非空 `tool_calls`。`reasoning_content` 不作为回答、不进入结果或异常。`finish_reason == "length"` 返回不可自动重试的 `output_truncated`；`finish_reason == "tool_calls"` 且携带调用时返回 `tool_calls_unsupported`；缺失、未知或冲突的结束原因及不合法响应为 `invalid_response`。本阶段不实现工具调用。此前未带 `finish_reason` 的模拟响应需要补齐该字段。

HTTP 200 的解析失败、截断或工具调用错误保留可验证的 `LLMError.usage`，缺失或不合法的 usage 为 None；不保存部分输出、思考内容或原始响应。调用方应保留错误中已知用量、避免把失败当作免费调用，并自行决定后续处理；客户端不自动重试。此前 32 Token 的真实调用是否确为截断无法从已丢失的结束原因证明，需以后续获授权测试的安全诊断判断。


## M2-08-01-FIX-01 调用与兼容

每次尝试的结果和执行错误携带应用侧 `call_id`；重复处理同一个结果必须使用相同 ID，`add_result()` 会去重。`add(usage, call_id=...)` 也需要显式传入规范 UUID；旧的无 ID `add(usage)` 写法不再支持。该 ID 只用于应用侧记账，不是供应商幂等键；新请求总是新 ID。结果不明或不可验证 usage 会使累计保持不完整，旧状态没有完整性标记时不能恢复为完整。

保留 256 的既有全局默认上限以避免擅自扩大调用成本；后续每个 Agent **必须显式传入任务级 max_tokens**，Planner 预算在 M2-08-02 契约中确定。失败时不要记录 traceback 的局部变量或客户调用堆栈中的秘密；LLM 边界会清除底层异常链及内部帧，但调用方自己的栈帧可能仍含用户数据。
# Planner 超时与安全诊断补充

普通 LLM 调用继续使用 `LLM_TIMEOUT_SECONDS` 作为读取空闲超时（默认 30 秒）。Planner 单独使用 `LLM_PLANNER_READ_TIMEOUT_SECONDS`，默认 120 秒，可配置范围 `(0, 600]`；连接、连接池和写入空闲超时上限分别为 10、10、20 秒，不超过该次读取超时。HTTPX 的读取超时是单次读取等待上限，并非整个请求的绝对耗时上限。Planner 的输出上限仍为已确认的 2048 Token，不自动重试。

`ConnectTimeout` 和 `PoolTimeout` 表示尚未发送；`WriteTimeout` 和 `ReadTimeout` 结果未知，仍需人工对账。读取阶段无法从现有 HTTPX 异常进一步区分等待响应头与读取响应体。所有错误均不自动重试；不确定结果不能据此证明没有费用。

Planner 调用会向 `logs/llm-diagnostics.log` 追加经过白名单过滤的调用 ID、耗时、错误分类、请求阶段、HTTP 状态及规范 UUID 格式的供应商 request ID；不记录密钥、Prompt、模型内容或异常原文。日志写入失败不会重放调用。仅在服务器返回响应时才能得到对应 HTTP 状态和供应商请求 ID；旧超时记录没有这些信息，不能事后推断。

客户端将本地唯一 `call_id` 作为供应商请求体的 `request_id` 用于关联，不代表供应商保证幂等或 exactly-once。参考[智谱对话补全 API](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%AF%B9%E8%AF%9D%E8%A1%A5%E5%85%A8)。`glm-5.3-flash` 仅支持开启思考，本次不关闭思考或改用其他模型；当前请求未显式设置 `reasoning_effort`，沿用供应商默认值，见[模型说明](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)。
